==============================================================
 MTB / MTC 编码器  ——  打包与安装说明
 版本 v1.2    2026-11-15    Windows 10/11 实测
==============================================================

这个包里有源码、有测试、有两份报告，还有一个已经打好的 Windows
单文件程序 dist\MTBViewer.exe（29.4 MB）。

v1.2 相对 v1.1 多了四件事：图片支持透明（alpha）、视频容器带帧率
和音轨（MTC v2）、PNG/JPG/MP4 等主流格式双向互转（convert / export
两条新命令）、以及 360p～4×4K 的尺寸预设。查看窗口里的帧率、字节数
之类指标全部删掉了，图片打开就是一张图。

下面按"我现在就想用"、"我想自己重新打包"、"我想搬到别的系统"
分开写。急着用就跳到 第二节 和 第十节。

--------------------------------------------------------------
 二、三种用法，任选一种
--------------------------------------------------------------
【方式 A】双击 .mtb / .mtc 文件
  本机上后缀关联已经写好了，现在双击 samples\demo.mtc 会直接
  用 dist\MTBViewer.exe 打开并自动播放。
  换到别的电脑上，先在那个电脑上跑一次：
      python deploy\windows_register.py --exe "<那个电脑上的>\dist\MTBViewer.exe"
  （--exe 也可以省掉，那样会关联到本机 Python 的 pythonw + launcher）

【方式 B】只用 exe，不需要装 Python
  · 双击 dist\MTBViewer.exe：弹出"打开 MTB / MTC 文件"对话框
  · 把文件拖到 exe 图标上：Windows 会把路径当参数传进去
  · 命令行：dist\MTBViewer.exe "D:\pics\a.mtb"
  注意：onefile 的 exe 每次启动要先把内容解压到临时目录，
  首次启动大约 3–8 秒，之后会快一点。要更快就用下面方式 C，
  或者按第五节用 --onedir 重新打一份。

【方式 C】源码方式（本机或任何装了 Python 3.10+ 的机器）
  依赖：numpy、Pillow（tkinter 是 Python 自带的）
      pip install numpy pillow
  · 看图/播放（窗口里只有画面，不显示帧率等指标）：
      python -m mtcodec open samples\demo.mtc
  · 编码（输出不写扩展名会自动补 .mtb / .mtc）：
      python -m mtcodec encode photo.png samples\photo_c -q 80
      python -m mtcodec video-encode frames\ samples\demo -q 80 --gop 6
  · 解码 / 查头：
      python -m mtcodec decode a.mtb back.png
      python -m mtcodec info a.mtb
      python -m mtcodec video-info a.mtc
  · 格式互转（v1.2 新增，详见第十节）：
      python -m mtcodec convert 图片.png 图片.mtb --size 1080p -q 80
      python -m mtcodec convert 视频.mp4 视频.mtc --size 720p --fps 12
      python -m mtcodec export 图片.mtb 图片.jpg
      python -m mtcodec export 视频.mtc 视频.mp4
  · 当库用：
      import mtcodec
      blob = mtcodec.encode_image(img, quality=85, subsample="420")
      img2 = mtcodec.decode_image(blob)

 三、本机的 Windows 关联到底写了什么
--------------------------------------------------------------
 全部写在 HKEY_CURRENT_USER，不需要管理员权限，也不影响系统其它
 文件类型：

  HKCU\Software\Classes\.mtb        (默认) = MTB.Image
  HKCU\Software\Classes\.mtc        (默认) = MTB.Video
  HKCU\Software\Classes\MTB.Image   (默认) = "MTB 图像"
                                    FriendlyTypeName = "MTB 图像"
                                    Content Type   = image/x-mtb
                                    PerceivedType  = image
        \DefaultIcon   (默认) = ...\deploy\icons\mtb.ico
        \shell\open    (默认) = "打开"
        \shell\open\command (默认) = "<路径>\dist\MTBViewer.exe" "%1"
  HKCU\Software\Classes\MTB.Video   结构同上，图标换成 mtc.ico，
                                    Content Type = video/x-mtc

  · 撤销全部关联：
      python deploy\windows_register.py --unregister
  · 改成用源码方式打开（不依赖 exe）：
      python deploy\windows_register.py --python <带 numpy/Pillow 的 python.exe>
  · 改回 exe 方式：
      python deploy\windows_register.py --exe "<路径>\dist\MTBViewer.exe"
  · 路径变了（整个文件夹挪走、exe 改名），重跑一次上面任意一条即可。

  关于"设为默认"：Win10/11 不允许程序静默把自己变成默认打开方式。
  系统的 UserChoice 带哈希校验，只有用户自己在"打开方式"里勾一次
  "始终使用此应用"才能写进去。我们能做的是把 ProgID、图标、
  打开命令都注册好——第一次双击系统就认得"MTB 图像"，勾一次之后
  就永久生效。

 五、用 PyInstaller 自己重新打包（本次用的就是它）
--------------------------------------------------------------
 1) 安装（只需要装一次）
      pip install pyinstaller

 2) 一条命令（在本项目根目录执行，路径按需改）
    （行尾的 ^ 是 cmd 的续行符；用 PowerShell 的话换成反引号 ` ）
      python -m PyInstaller --noconfirm --clean --onefile --windowed ^
        --name MTBViewer --icon deploy\icons\mtb.ico ^
        --paths . --hidden-import mtcodec.viewer --hidden-import PIL.ImageTk ^
        deploy\mtb_app.py

 3) 或者直接跑本包里的脚本（内容就是上面那条命令）
      python tools\build_exe.py

 参数逐条解释：
   --onefile          打成单文件。等价 --onedir 会打成一个文件夹，
                      启动快，但要把整个文件夹一起拷给别人。
   --windowed         不带黑色控制台窗口（GUI 程序用这个）。
                      调试期间先换成 --console，报错能看见。
   --icon             给 exe 本身指定图标，必须是 .ico。
   --paths .          把项目根目录加进模块搜索路径，否则找不到 mtcodec。
   --hidden-import    告诉 PyInstaller 这里有个它静态分析看不到的导入。
                      mtcodec.viewer 和 PIL.ImageTk 都容易漏，漏了就会
                      启动直接闪退。
   --clean --noconfirm 清掉上次的缓存和旧产物，避免打包到一半互相打架。

 产物：
   dist\MTBViewer.exe   最终程序（本机实测 29.4 MB）
   build\               中间产物，可以删
   MTBViewer.spec       打包配置，下次可以直接 pyinstaller MTBViewer.spec

 想更小 / 想更快：
   · 换 --onedir：启动 1 秒内，但交付的是一个文件夹。
   · 加 --exclude-module tkinter.test 之类，剔除用不到的模块。
   · UPX 压缩（--upx-dir <upx目录>）能再小 20%–40%，但被杀软误报的
     概率会明显上升，个人用可以不管。
   · 排除 numpy 的测试套件（--exclude-module numpy.tests）也能省几 MB。

 常见报错与处理（本机真踩过的排在最前）：
   · "Can't find a usable init.tcl" / 打出来的 exe 双击闪退：
     打包用的那个 Python 缺 Tcl/Tk 数据文件。Windows 上安装的官方
     Python 都自带 tcl\tk 目录；但某些绿色版、嵌入版、被裁剪过的
     runtime 里 tkinter 只剩空壳（本机一开始用的就是这种），
     用这种 Python 打包出来的窗口程序必然闪退。
     处理：改用带完整 Tcl/Tk 的官方 Python 打包（python.org 安装包
     勾 "tcl/tk and IDLE"），或者把 tcl86t.dll、tk86t.dll 和
     Lib\tcl8.6、Lib\tk8.6 目录一起补进 --add-data。
   · ModuleNotFoundError: No module named 'numpy' / 'PIL'：
     PyInstaller 在另一个 Python 里跑，没装依赖。用同一个 Python
     装齐：pip install numpy pillow，再打。
   · 双击闪退、看不到任何提示：先 --console 重新打一份，从控制台看
     报错；或者在 exe 里加 try/except 写日志文件。
   · 杀软报毒：PyInstaller 的 onefile 是自解压行为，误报很常见。
     处理：加白名单、用 --onedir、或自己签名。
   · 打出来的 exe 在别人电脑上提示缺 MSVC 运行库：
     装一次 Microsoft Visual C++ Redistributable（x64）。
   · exe 位数：打包 Python 是 64 位就打不出 32 位程序，目标机器必须
     对得上。


--------------------------------------------------------------
 六、用 Nuitka 打包（可选，启动更快）
--------------------------------------------------------------
 Nuitka 把 Python 编译成 C 再编译成 exe，启动比 PyInstaller 快，
 反编译也更难，代价是要有 C 编译器、首次编译慢。

 1) 安装
      pip install nuitka ordered-set zstandard

 2) 编译器二选一
      · MSVC：装 Visual Studio Build Tools，勾"使用 C++ 的桌面开发"
      · MinGW64：Nuitka 可以先 --mingw64 自动下载一份

 3) 命令（本项目）
      python -m nuitka --onefile ^
        --enable-plugin=tk-inter ^
        --windows-console-mode=disable ^
        --windows-icon-from-ico=deploy\icons\mtb.ico ^
        --include-package=mtcodec ^
        --output-filename=MTBViewer.exe ^
        deploy\mtb_app.py

 要点：
   --enable-plugin=tk-inter  必须加，否则 tkinter 的 Tcl/Tk 数据不会
                             被带进去，exe 一样闪退。
   --windows-console-mode=disable  等价 PyInstaller 的 --windowed
   首次编译 3–10 分钟很正常，numpy 这种大包尤其慢。
   体积：常见 40–80 MB（--onefile 自带压缩，比 PyInstaller 略大或
   接近，但启动更快）。

 两者怎么选：
   · 只想快点拿到能双击的 exe、不折腾环境 → PyInstaller
   · 在意启动速度、想少被人反编译、机器上已有编译环境 → Nuitka


--------------------------------------------------------------
 七、Linux / macOS 上怎么办（重要：不能跨平台打包）
--------------------------------------------------------------
 PyInstaller 和 Nuitka 都不能交叉编译：Windows 上打不出 Linux 的包，
 反之亦然。必须在目标系统上各打一次。

 Linux：
   pip install numpy pillow pyinstaller
   pyinstaller --onefile --windowed --name mtbviewer ^
     --add-data "src:mtcodec" deploy/mtb_app.py
   （Linux 上 --add-data 的分隔符是冒号，Windows 上是分号）
   再补一个 .desktop 文件 + xdg-mime 注册，才能双击生效：
     xdg-mime default mtbviewer.desktop image/x-mtb
     xdg-mime default mtbviewer.desktop video/x-mtc
   图标用 assets/icons 里的 512 png。

 macOS：
   同上命令能出 .app；要双击生效还得改 Info.plist，加
   CFBundleDocumentTypes（声明 .mtb / .mtc 和对应的 icon）；
   也可以用 duti 注册：
     duti -s com.example.mtbviewer .mtb all
   注意苹果的 Python 必须用 python.org 的安装包（自带 Tk），
   Homebrew 的 python 默认不带 tkinter。

--------------------------------------------------------------
 十、格式互转与尺寸（v1.2 新增，命令与边界都在这里）
--------------------------------------------------------------
 目标只有一个：让 .mtb / .mtc 能进也能出，不把文件锁死在自己的
 格式里。

【10.1 两个新命令】
  convert   主流格式 -> .mtb / .mtc
  export    .mtb / .mtc -> 主流格式
  两者都按扩展名自动判断类型，扩展名写错会直接报错，不会瞎猜。

  convert 参数：
    -q            质量，默认 80。越小体积越小、细节越少。
    -s / --size   尺寸预设或具体尺寸（见 10.3）。
    --lossless    图像无损（体积会大很多，逐像素一致）。
    --fps         抽帧帧率，默认 12。
    --gop         I 帧间隔，0 表示全帧内（体积大、随便跳转）。
    --max-frames  最多抽多少帧，默认 24。
    --start       从第几秒开始抽，默认 0。
    --no-audio    不要把音轨塞进 MTC（默认是塞的）。

  export 参数：
    目标写 .mp4 就出 MP4（自动把 MTC 里的音频交给 ffmpeg 封装），
    目标写 .png / .jpg 就出图，目标写目录名就导出全套帧 + audio.wav。

【10.2 支持的格式】
  进（-> MTB）：PNG、JPG、BMP、WEBP、TIF、GIF、APNG（动图取多帧）
  进（-> MTC）：MP4、MOV、MKV、AVI、WEBM、M4V 等 ffmpeg 能解的容器
  出（MTB）：  PNG（保留透明）、JPG、BMP、WEBP
  出（MTC）：  MP4（H.264 + AAC，含音轨）、PNG 帧序列 + WAV

  透明的处理：
    · MTB 完整支持 alpha，alpha 走无损平面，往返 PNG 后逐位相等。
    · 透明像素的 RGB 在编码前被置 0，避免边缘出现脏色；导出 JPEG 时
      会自动合到白底（JPEG 没有透明）。
    · MTC 不支持 alpha：动图带透明转成视频后透明区变成黑/白底，
      这是视频容器本身的限制，不是解码错误。

【10.3 尺寸预设】
  360p   640 x 360          1080p  1920 x 1080
  480p   854 x 480          1440p  2560 x 1440
  540p   960 x 540          2k     2560 x 1440
  720p  1280 x 720          4k     3840 x 2160
  4x4k  7680 x 4320         8k     7680 x 4320

  · 也可以直接写具体尺寸：--size 1920x1080
  · 等比缩放到预设框内，不拉伸；竖图自动对调宽高
    （一张 1080x1920 竖图写 --size 1080p 会得到 1080x1920，不会变横）
  · 实测耗时（q80、纯 Python、单线程）：
      360p 0.2 s   1080p 1.2 s   2048² 3.2 s
      4K   3.4 s   4320² 9.4 s    7680x4320 16.6 s（解码 18.0 s）
    最坏情况（把 800x450 这种小图放大到 8K）要 82 s——画面越平滑
    越慢，纯 Python 逐符号算术编码就是这个量级。

【10.4 音轨怎么进去的】
  ffmpeg 把音轨解成 44.1 kHz 立体声 PCM，整段以 WAV 塞进 MTC 头部
  之后的音频段，不重编码。好处是没有二次损失、解出来就是原始波形；
  代价是 1 秒 172 KB，实测占 MTC 体积的 24%–59%，比 12 帧画面还大。
  想更省体积，得把音频改存 AAC/Opus 并在头里标记编码类型，这一版
  没做（改了就破坏"解出来即原始 PCM"的简单性）。

【10.5 播放时的音画同步是粗同步】
  画面按头里的 fps 定时刷新，音频用 winsound 异步启动，没有逐帧
  PTS 对齐。短片没问题；长片会慢慢漂。这是有意的取舍：要精确同步
  就得把音轨切成每帧对应的小段，容器也要改，工作量比这一版大得多。
  另外 winsound 是 Windows 专有，Linux/macOS 上画面能播、声音不响。

【10.6 依赖 ffmpeg】
  视频相关的功能（读 MP4、导出 MP4、抽音轨）必须调 ffmpeg：
    · PATH 里有 ffmpeg 就直接用；
    · PATH 里没有，会退到 imageio_ffmpeg 自带的那个；
    · 都没有就报错提示，图片功能不受影响。
  本机实测用的是：
    D:\ffmpeg-2026-11-05-git-0893feba65-essentials_build\bin\ffmpeg.exe
  换机器时把 ffmpeg.exe 放进 PATH（或整目录加进环境变量）即可。

【10.7 一句提醒】
  MTB/MTC 是"存中间结果"的格式，不是"存片子"的格式：MTC 现在只存
  抽出来的十几帧（默认上限 24 帧），不是整段视频的压缩替代品。
  要长期存片，仍然用 MP4；要用它做实验、做对比、做归档的体积优化，
  再走 convert。

【10.8 这一版的实测结论（详见 格式互转与多分辨率测试报告.html）】
  · 7 张 4.28 MB 级壁纸 -> 300 KB 上下，压缩比 20–35 倍
  · 4 段 MP4（5.6–35.5 MB）-> 291–703 KB，音轨全部保留
